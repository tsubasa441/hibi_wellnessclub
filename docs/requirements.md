## 1. プロジェクト概要

### 背景

Hibi はヨガ・トレーニング・ランニング・ボクシング・ピラティスなど月 4〜5 回のフィットネスイベントを運営するコミュニティ。現在、予約・決済・参加履歴・紹介導線が整備されておらず、運営の属人化と参加者エンゲージメント低下が課題。今後、イベント回数の増加、法人への導入など、さらにスケールさせていく際に、属人化の解消、参加者のエンゲージメント向上、法人に導入するにあたって実績の蓄積・ビジネスとしての信頼の構築が必須。

### 目的

- 参加者が『Hibiの一員であること』を自慢したくなり、自分自身のライフスタイルに誇りを持てる状態をつくる・運動を通じて自身の成長を実感できる状態を作る
- エンゲージメントの向上
- イベント参加の継続率アップ
- 自己実現欲求の最大化（自分が何者かでいられていること・誰かの役に立てていることの証明）

### 対象ユーザー

フィットネスに興味のある 20〜40 代の社会人。想定 100〜500 人規模。

## 2. 機能要件

### A. イベント予約・決済

- イベント一覧表示（カードは日時（開始〜終了）・イベント名・開催場所と、アイコンの下に種別。料金・定員は一覧に出さず詳細画面で表示。2026-10-18 依頼者の指定で変更）
- イベント詳細ページ（残席数をリアルタイム表示）
- キャンセル待ち（2026-10-25 追加）：満席のイベントで、未予約の人が「キャンセル待ちをする」を押すと登録される（満席でなければボタンは押せない。予約済みの人には出さない）。キャンセル等で空きが出たら、登録者全員にメールで知らせ（先着順で予約）、キャンセル待ちを終了する
- Square または PayPay での事前決済
- 予約確認メール送信
- キャンセルポリシー：イベント2日前までキャンセル可、1日前・当日はキャンセル自体は可能だが返金対象外（充当したポイントは払い戻す。2026-10-28 依頼者の指定）
- キャンセル時の返金フロー：Square / PayPay は API で自動全額返金、無料イベントは返金なし
- イベントごとの選択項目：管理者が任意個数（最大10）設定できるプルダウン選択項目。ユーザーはイベント詳細画面で回答してから予約する。項目ごとに「必須/任意」「単一/複数選択」を設定可能。金額・ポイント・返金には影響しない情報項目。回答は参加者一覧・CSV に表示される
- チェックイン：予約済みイベント画面の各カードから、イベント開始30分前〜開始15分後の間だけ「チェックイン」できる（それ以外はボタン非活性。2026-10-25、依頼者の指定で「開始時刻〜終了時刻」から変更）。チェックインが「参加」の唯一の条件で、参加ポイント・月間ボーナス・クラスバッジ・ランクの累計参加回数はチェックイン済みの予約のみでカウントされる。管理者は参加者一覧・CSV でチェックイン状況（済/未・時刻）を確認できる
- 終了したイベントの表示：イベントの終了時刻（未設定なら開始＋2時間）を過ぎた予約は、ホーム・予約済みイベント・チェックイン画面のカードから消える。画面を開いたまま終了時刻を過ぎた場合も、自動で表示を取り直して消す（`src/components/RefreshAt.tsx`。2026-10-18 追加）

### B. 累計参加数

- 参加回数の可視化（プロフィール画面）。カウント対象は**チェックイン済み**の予約のみ
- 参加履歴一覧（スコープ外）

### C. 紹介システム

- ユーザーごとのユニーク紹介コード発行
- 紹介コード経由で新規登録 → `referrals` を pending で作成。被紹介者が初めてイベントにチェックインした時点で、紹介者・被紹介者双方へ 200pt 付与（2026-10-18 依頼者の指定で「イベント終了後」から変更）
- 紹介実績数の表示（Impact 画面のラベルは「あなたから広がった幸せの数」、2026-10-15 に依頼者の指定で「紹介したお友達」から変更）。数値は、自分が紹介した人（1代目）と、その人たちが紹介した人（2代目）のうち、初回イベントに参加して紹介が確定（`rewarded`）した人数の合計。3代目以降は数えない（2026-10-17、依頼者の指定。`src/lib/referrals.ts` の `countReferralReach`）。月間の紹介バッジは従来どおり自分が直接紹介した人数のみ。紹介履歴の一覧は 2026-10-14 に依頼者の指示で Impact 画面から削除

### D. ゲーミフィケーション

- ポイント制度（参加・紹介でポイント獲得）
- バッジシステム（達成条件別）

### E. ジャーナル機能（2026-09-13 現フェーズ対象外に変更、次フェーズで再実装予定）

- 毎日の心身の健康状態・気持ちをログとして残せる機能（ホーム画面からのクイック入力のみ）
- 振り返り画面・グラフ表示はユーザー向けには提供しない
- journals テーブルのデータは将来の法人（ToG）向けデータ提供・健康影響レポートの原資として保管する
- **現状**：ホーム画面の入力導線・`POST /api/journals` は無効化済み（機能停止）。`journals` テーブルと既存データは保持し、新規収集のみ停止している。次フェーズで実装を再開する

### F. 管理者機能

- イベント作成・編集・削除（2026-10-27 から削除は DB から完全に消す。終了したイベントはそのまま削除し、参加回数・ポイント・支払いの記録は予約側に残る。これからのイベントの削除は「中止」として、予約者全員に全額返金（ポイントも払い戻し）し、中止のお知らせをメールで送る。開催中は削除できない）
- イベントの選択項目（`event_options`）の設定（項目名・選択肢・必須/任意・単一/複数選択）。編集時は置き換え方式
- 参加者一覧・CSV エクスポート（選択項目の回答・チェックイン状況を含む。選択項目のラベルが CSV の動的列になる）
- `profiles.is_admin` で管理者を判定。付与はアプリ内UIではなく Supabase Studio から手動で行う運用（@docs/authdesign.md 参照）

### G. アカウント管理

- ユーザー自身によるアカウント削除（下ナビの「マイページ」→「退会」）。アカウントと、ポイント・バッジ・紹介・お問い合わせ等のデータはすべて削除する。予約・支払いの記録だけは、誰のものか分からない形で残す（2026-10-27 に「匿名化して残す」から変更。@docs/authdesign.md 参照）。これからのイベントの予約がある間は退会できない。管理者アカウントはこの導線では削除できない
- マイページ（`/mypage`）で、ニックネーム変更・メールアドレス変更・パスワード変更・クレジットカードの登録/変更・ログアウト・アカウント削除を行える（2026-10-16 にヘッダーの歯車アイコン（設定ドロワー）から移設）
- メールアドレス変更（2026-10-24 追加）：新しいアドレスと現在のパスワードを入力して申し込み、今のアドレスと新しいアドレスの両方に届く確認メールのリンクを押すと切り替わる。以降は新しいアドレスでログインする。既に他のアカウントが使っているアドレスには変更できない（@docs/authdesign.md 参照）

### H. お問い合わせ（2026-10-17 追加）

- ユーザーはマイページの「お問い合わせ」（`/support`）から、運営とチャット形式でやり取りできる（ユーザー1人につき1本のスレッド。本文は1〜2000文字）
- ユーザーが送ると、運営（hibi.wellnessclub@gmail.com）に本文と管理画面へのリンクをメールで通知する
- 運営は管理画面のお問い合わせ（`/admin/support`）で一覧（未読・未返信の表示）とやり取りを確認し、返信する（Gmail から直接の返信はできない）
- 運営が返信すると、ユーザーにメールで知らせ（本文は載せない）、下ナビの「マイページ」とマイページの「お問い合わせ」に未読の赤い点を付ける。開くと既読になる
- 画面を開いている間は20秒ごとに新着を取り直す（リアルタイム通信は使わない）

## 3. 非機能要件

| 項目 | 内容 |
|------|------|
| 想定ユーザー数 | 100〜500人 |
| レスポンシブ | スマホファースト |
| 言語 | 日本語 UI |
| 認証 | Supabase Auth |
| セキュリティ | Row Level Security、主要APIのレート制限、セキュリティヘッダー（CSP等） |
| エラー監視 | Sentry（DSN未設定時は無効） |
| 可用性 | 99% 以上 |
