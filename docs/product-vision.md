# Hibi プロダクトビジョン

## 解決したい課題

フィットネスコミュニティ Hibi は月 4〜5 回のイベント（ヨガ・トレーニング・ランニング・ボクシング）を運営している。現在は予約・決済・参加履歴・紹介導線が整備されておらず、運営の属人化と参加者エンゲージメント低下が課題。

## ユーザー像

- フィットネスに興味のある 20〜40 代の社会人
- 想定規模: 100〜500 人

## プロダクトが目指す状態

- 参加者が「Hibi の一員であること」を自慢したくなり、自分のライフスタイルに誇りを持てる
- 運動を通じた自己成長を実感できる
- 友人紹介によってコミュニティが自然に広がる

---

## やること（スコープ内）

| フェーズ | 内容 |
|---------|------|
| Phase 1 | 認証・イベント予約・Square / PayPay 決済・キャンセル返金・メール通知 |
| Phase 2 | ランク・ポイント・月間バッジ・紹介システム・ジャーナル |
| Phase 3 | 管理者機能（イベント作成・参加者管理・CSV エクスポート）・法人向けレポート |

## やらないこと（スコープ外）

- ライブ配信・動画コンテンツ
- サブスクリプション / 月額プラン
- ユーザー間のチャット・DM 機能
- ジャーナルの振り返り画面・グラフ表示（データは ToG 向け蓄積のみ）
- ポイントの現金化（銀行振込・現金引き出し等）や外部商品との交換
- iOS / Android ネイティブアプリ（Web のみ）

> ポイントを使ったイベント参加費の割引（1pt = 1円、予約時にその場で充当）はスコープ内。現金化・外部商品交換とは区別する。

---

## アーキテクチャの意図

- **Server Components 優先**: データ取得はサーバー側で完結させ、クライアント JS を最小化する
- **Supabase RLS**: テーブル単位でアクセス制御し、API Routes を介さない直接クエリを防ぐ
- **ポイント付与の遅延評価**: ホーム画面ロード時に未付与分をまとめて処理することで、決済フローをシンプルに保つ
- **月次 Cron**: バッジボーナスポイントは Vercel Cron で月初に一括付与する

---

## 将来の拡張方針

- 法人（ToG）向け: ジャーナルデータを集計した健康影響レポートの提供
- 管理者ダッシュボード: イベント作成・編集・参加者 CSV エクスポート
- イベント種別の拡張: 新種別追加時は `events.event_type` と badges の `condition_type` を追加するだけで対応可能な設計
