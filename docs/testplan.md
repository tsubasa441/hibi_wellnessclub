# Hibi テスト計画

---

## テスト方針

- ユニットテスト：ロジック関数（ポイント計算・バッジ判定）
- E2E テスト：主要ユーザーフロー（予約・決済）
- 手動テスト：決済サンドボックス・UI 確認

---

## テスト対象

### A. ユニットテスト（Vitest）

| テスト対象 | 内容 |
|-----------|------|
| ポイント計算 | 初回参加・2回目以降・紹介成功・ストリークの付与ポイントが正しいか |
| バッジ付与条件 | 参加回数・紹介数・連続参加週の判定が正しいか |
| 管理者判定（`isAdmin`） | `profiles.is_admin` の true/false/レコードなしを正しく判定するか |
| CSV生成（`toCsv`） | ヘッダー生成・カンマ/改行/ダブルクォートのエスケープ・空配列時の挙動・BOM付与 |
| 管理者APIの認可判定 | イベント作成・更新・削除・参加者CSVエクスポートの各APIで未認証401／非管理者403が正しく返るか |
| イベント削除の論理削除検証 | `DELETE /api/admin/events/[id]` が物理削除ではなく `status` を `cancelled` に更新するのみであること |

### B. E2E テスト（Playwright）

| フロー | 手順 |
|--------|------|
| 新規登録 | `/login`（SIGN UP タブ）→ 入力 → `/register-complete` に遷移 |
| ログイン | `/login`（SIGN IN タブ）→ 入力 → `/home` に遷移 |
| 無料イベント予約 | `/events/[id]` → 予約ボタン → 予約済み表示 |
| 有料イベント予約 | `/events/[id]` → `/checkout` → 決済 → `/events/[id]?booked=1` |
| 紹介コードシェア | `/impact` → URLコピー確認 |

### C. 手動テスト

| 確認項目 | 方法 |
|---------|------|
| Square 決済 | Square サンドボックスのテストカードで決済完了まで確認 |
| PayPay 決済 | PayPay サンドボックスで決済完了まで確認 |
| レスポンシブ | Chrome DevTools でスマホ表示（375px・390px）確認 |
| 残席数表示 | 定員上限まで予約し「満席」表示になるか確認 |
